# README Assets — Reproducible Screenshot Capture

GitHub #381 (PR 1 of #356). ADR 2026-10-13 "README Assets Are Generated From Synthetic Data, Never
Hand-Edited" (`AI/DECISIONS.md`). Spec `AI/architect_spec_readme_capture.md`. Invariant
`soos-invariants::readme_assets_contract`. Walkthrough `AI/walkthroughs/207_readme_capture.md`.

Every image the README shows is generated by a script from synthetic data. Nobody adds or edits an
image by hand, and no real face, account, host name or device ever appears in one.

## 1. Layout

```text
Docs/assets/
├── MANIFEST.toml          # generated: path, generator, SHA-256, source = "synthetic"
└── screenshots/
    ├── gui-live-inspection.png      # soos-gui live diagnostic
    ├── gui-guided-enrollment.png    # soos-gui guided enrollment (user alice)
    ├── gui-profiles.png             # soos-gui enrolled profiles (one synthetic profile)
    └── web-<scene>-<light|dark>.png # phone web app captures (unlocked, locked-alerts; light, dark)
```

## 2. Budget and formats (assumed — owner to confirm)

| Rule | Value |
|---|---|
| Formats | PNG, still WebP, SVG only |
| Per file | at most 1 MiB (1 048 576 bytes) |
| Total `Docs/assets` (manifest excluded) | at most 8 MiB |
| File count | at most 32 |
| Animation | refused (APNG `acTL`, WebP `ANIM`/`ANMF`, VP8X animation flag) |
| Metadata | refused: PNG keeps only `IHDR PLTE tRNS gAMA cHRM sRGB pHYs IDAT IEND`; WebP refuses `EXIF`, `XMP `, `ICCP`; SVG refuses `<metadata`, `<image`, editor namespaces, scripts and remote or `data:` references |
| Provenance | every file is listed in `MANIFEST.toml` with generator `soos-gui readme_snapshots` (`screenshots/gui-*`) or `scripts/capture_readme_web.sh` (`screenshots/web-*`) and a matching SHA-256 |
| README references | every README image resolves under `Docs/assets/` and has alt text; the only external images allowed are `img.shields.io` badges and this repository's workflow `badge.svg` |

The three GUI screenshots total about 200 KB and the four web app captures about 450 KB.

## 3. GUI screenshots (hardware-free, runs in CI)

```bash
scripts/capture_readme_assets.sh          # regenerate gui-*.png and MANIFEST.toml
scripts/capture_readme_assets.sh --web    # also run the optional web capture (section 4)
```

How it works:
- `soos-gui` has a dev-only, non-default feature `readme-capture` exposing `soos_gui::app::capture`.
  `capture_app` builds a real `SoosApp` for one `CaptureScene` (`LiveInspection`, `GuidedEnrollment`,
  `Profiles`) with every side effect replaced: no vision worker, a thread-free static camera, a fixed
  daemon probe (no `systemctl`), a refusing privileged executor (no `pkexec`), no biometric store, and
  the identity `alice` / uid 1000 instead of the host account.
- The camera image is `soos_test_fixtures::readme::create_placeholder_face_frame`, a flat drawn
  illustration aligned with the mock detector box. The mock detector, liveness and embedding models
  run once on it. **Every detection, liveness and match value in these screenshots comes from mock
  models on a drawn face, not from the real models**; README captions must say so. FPS and latency
  are fixed constants (30 FPS, 12.5 ms).
- `crates/gui/tests/readme_snapshots.rs` drives the real `eframe::App::ui` with the egui harness of the
  workspace's egui 0.35 (`eframe::Frame::_new_kittest`, fixed `RawInput`, 1120×780 points at 1 pixel
  per point, 3 passes), tessellates the output and rasterizes it with a small CPU rasterizer
  (`crates/gui/tests/readme_capture/`). No GPU, no display server, no new crate except the `png`
  dev-dependency already in `Cargo.lock`. `egui_kittest` is deliberately not used (its pixel
  snapshots need `wgpu` and a GPU or lavapipe).
- Normal test runs compare each rendering with the committed PNG: a scene fails when more than 0.002 %
  of its pixels (17 pixels) differ by more than 16 levels on a channel. The failure message names the
  script. `SOOS_UPDATE_README_ASSETS=1` (set by the script) rewrites the PNGs and is refused when `CI`
  is set.

**Regeneration is not test weakening.** The PNGs are generated data, not assertions. When a pull
request changes a captured GUI screen on purpose, it reruns `scripts/capture_readme_assets.sh` and
commits the new PNGs and manifest; the reviewer looks at the image diff. Each regeneration adds at
most the asset budget to the git history.

No container is needed: the capture is a plain `cargo test` with no system library beyond the
workspace build (deviation from the epic's Docker proposal, recorded in the ADR).

## 4. Phone web app captures (optional, needs a browser)

```bash
CHROME=/usr/bin/google-chrome-stable scripts/capture_readme_web.sh   # or chromium
scripts/capture_readme_assets.sh   # refresh MANIFEST.toml afterwards
```

- `tests/fixtures/examples/readme_web_fixture_server.rs` (std only, binds `127.0.0.1:0`, at most 16
  connections, 2 s I/O timeouts, 8 KiB request head, lifetime clamped to 1–300 s) serves the files of
  `crates/remote/assets` and canned JSON built by `soos_test_fixtures::readme_web::route`: auth state,
  status, alerts, push (disabled), camera (idle), offline history (recording, synthetic intervals
  relative to the capture time, GitHub #398) and an event stream with status, alerts and battery
  events, plus the fixture-only pages `/readme/tour-seen` and `/readme/capture` (GitHub #448, below). Scenes `unlocked` and
  `locked-alerts`. The bodies carry the exact keys of the `soos-remote`
  types (checked against the sources) and no identity: no login, host name, IP address, passkey id or
  push endpoint. `soos-remote` itself gains no flag, route or mode.
- The script opens each scene in an already installed headless Chrome/Chromium with a throw-away
  profile at 390×844 CSS pixels, device scale factor 2, light and dark, then strips every PNG
  metadata chunk (`--strip-png`). It installs and downloads nothing and is never a CI step.
- **Fixed synthetic clock**: every scene and theme shows the same instant,
  `soos_test_fixtures::readme_web::FIXED_CAPTURE_UNIX_MS` = 2026-10-01T09:41:00Z, never the real
  capture date. The server runs with `--clock fixed` and builds every body (status, alerts, offline
  history, event stream) from that instant; the screenshot is taken on the fixture page
  `/readme/capture`, which serves the assets' `index.html` with `<base href="/">` and an inline clock
  script (`CAPTURE_CLOCK_SCRIPT`) inserted before `app.js`, so `Date.now()` and `new Date()` return
  the same instant (`new Date(value)` is unchanged). The asset files are never modified. Every
  browser run has a pinned time zone and locale (`BROWSER_ENV`: `TZ=UTC`, `LANG` and `LC_ALL`
  `en_US.UTF-8`, `LANGUAGE=en_US`, plus the flags `--lang=en-US` and `--accept-lang=en-US`; GitHub
  #458), so the page shows "Updated 0 s ago", "idle for 12 min" and alerts at 09:38 AM (12 h clock)
  in both themes whatever the capture host's time zone and locale (a run on a host with a German
  locale gave a 24 h "09:38" before the pin), and a rerun gives byte-identical PNGs (checked on the capture host with the same
  Chrome build; another browser version or font set may render differently). The fixture server
  lives up to 240 s per scene (two browser runs per theme).
- **First-run tour**: the web app's feature tour (ADR 2026-10-17, GitHub #414/#418) opens on a fresh
  browser profile and would cover the page. The browser therefore first opens the fixture page
  `/readme/tour-seen` (`soos_test_fixtures::readme_web::TOUR_SEEN_PAGE`), which sets the app's own
  tour flag (`soos-remote-tour-v1` = `seen`) in the throw-away profile and replaces itself with `/`;
  a second browser run in the same profile then takes the screenshot of `/readme/capture`.
  Both pages are fixture-only; `soos-remote` gains no flag, route or mode (RAC20, RAC21).
- The four captures `web-unlocked-light.png`, `web-unlocked-dark.png`, `web-locked-alerts-light.png`
  and `web-locked-alerts-dark.png` are committed (GitHub #448) and shown in the README "Screenshots"
  section. They were produced by the agent with an installed Google Chrome; the owner's visual check
  is still pending (RAC18). Rerun the script and `scripts/capture_readme_assets.sh` after a change of
  the web app's look and commit the new PNGs and manifest (no Node toolchain, no Playwright
  container).
