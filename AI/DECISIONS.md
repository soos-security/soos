# Architectural Decision Records (ADR) Register

This file records immutable technical decisions to ensure consistency and prevent architectural drift or hallucination across development sessions. All decisions derive strictly from `ARCHITECTURE.md`.

## Active Decisions

* **[2026-09-12] IPC (Inter-Process Communication):** Exclusively use local Unix Domain Sockets (`SOCK_SEQPACKET` or framed `SOCK_STREAM`) with strict `SO_PEERCRED` kernel validation. Zero network sockets.
* **[2026-09-12] PAM Module (`pam_soos.so`):** Must **never** start an asynchronous runtime (Tokio). Exclusively use blocking standard library primitives (`std::os::unix::net::UnixStream`) with a strict 200–250ms timeout.
* **[2026-09-12] Panic Safety:** The PAM module catches all panics via `catch_unwind`. In any error or panic condition, it systematically returns `PAM_IGNORE` to silently fall back to password authentication.
* **[2026-09-12] Camera & Hardware Access:** The root daemon is the exclusive owner of the `/dev/video*` capture device. Use the `v4l` crate (not `nokhwa`) to utilize kernel MMAP buffers in production.
* **[2026-09-12] Artificial Intelligence Engine:** Use `ort` (ONNX Runtime) in CPU execution mode. Importing or linking OpenCV is strictly forbidden.
* **[2026-09-13] Project Naming:** The project is named `soos`. The PAM shared object is `pam_soos.so`, the privileged background process is `soos-daemon`. Legacy references to "ZTLH" or "pam_ztlh" are deprecated.
* **[2026-09-13] Codec & Framing:** Use `postcard` + `serde` for IPC payload serialization. JSON is forbidden. Maximum payload size is capped at 4,096 bytes with big-endian length prefix.
* **[2026-09-13] Commit Standard & Language:** Conventional Commits 1.0.0 is strictly enforced across the repository via `.githooks/commit-msg`. All codebase deliverables (code, docs, PRs, commits, walkthroughs) are authored in 100% English.
* **[2026-09-16] Production Hardening & Memory Hygiene:** Decrypted embeddings, biometric templates, and raw frames enforce `Zeroize` / `ZeroizeOnDrop`. Sensitive key and embedding allocations are protected against swap paging via best-effort kernel `mlock` page pinning. Cargo-deny blocks duplicate dependencies (`multiple-versions = "deny"`), security advisories, and non-permissive licenses.
* **[2026-09-20] Next-Generation AI Models:** The 4-model pipeline (UltraFace Slim 320 + landmark_5point + MobileFaceNet 128D + MiniFASNet) is replaced by a 3-model pipeline: **SCRFD 500M KPS** (unified face detection + 5-point landmarks, ~2.4MB, MIT), **ArcFace MobileFaceNet w600k** (512D embeddings, ~3.6MB, MIT), and **MiniFASNetV2** (80×80 anti-spoofing, ~1.8MB, Apache-2.0). SCRFD eliminates the separate landmark model, saving ~20ms latency.
* **[2026-09-20] SCRFD Detection Architecture:** SCRFD uses multi-stride (8/16/32) distance-to-border box decoding with grid-based anchors, replacing UltraFace's center-offset prior-based decoding. Input is BGR 640×640 with letterbox padding. Output tensors are parsed by ordinal grouping (3 per stride: score, bbox, kps).
* **[2026-09-20] Embedding Dimensionality:** Biometric embeddings are upgraded from 128D to 512D. Normalization denominator changes from 128.0 to 127.5 for exact symmetric [-1.0, +1.0] range. No migration required (development state, no enrolled users).
* **[2026-09-20] PAD Crop Strategy:** MiniFASNetV2 receives a 2.7× expanded bounding box crop (80×80, BGR, pixel/255.0 normalization) instead of the aligned 112×112 crop. This provides wider context for anti-spoofing analysis. PAD and embedding use different crops from the same detection.
* **[2026-09-20] MiniFASNetV2 Class Ordering:** The QingHeYang ONNX fork uses `[Live, Print, Replay]` ordering (Class 0 = Live). The `OrtPadDetector` constructor accepts a configurable `live_class_index` parameter defaulting to 0, with a startup validation test against known fixtures. *(Superseded by the 2026-09-29 entry below.)*
* **[2026-09-29] Release Panic Strategy = `unwind` (supersedes the `panic = "abort"` choice recorded in walkthrough 11):** The shipped `pam_soos.so` is built by `[profile.release]` in every packaging path (`scripts/build_*.sh`, `packaging/**`, Docker matrix). Under `panic = "abort"` every `catch_unwind` in the module is a no-op, so the Panic Safety decision above was not honored by the installed artifact: a panic (including an overflow trapped by `overflow-checks = true`) killed the PAM host (gdm, sudo, login, screen locker) instead of degrading to `PAM_IGNORE` (review finding PAM-01 / TCI-01, GitHub #148, reproduced in Docker: `pam_test_runner` aborted with exit 134). Rust cannot select the panic strategy per package, so the whole workspace release profile is `panic = "unwind"`; abort semantics are not retained elsewhere because Rust already aborts when a panic escapes an `extern "C"` function (the defense-in-depth `abort` used to provide at the FFI boundary), and a Tokio daemon benefits from task-level panic isolation. The value is pinned by `tests/invariants` and proven on the release-built artifact by Docker case T10 through the opt-in, never-packaged `fault-injection` feature of `soos-pam`.
* **[2026-09-29] MiniFASNetV2 Live Class Index — Single Source of Truth (supersedes the 2026-09-20 "Class Ordering" entry):** The shipped `minifasnet_v2_80x80.onnx` is interpreted with the upstream Silent-Face-Anti-Spoofing class order `[PrintPhoto, Live, ScreenReplay]`, i.e. **live class index 1** (upstream `test.py`: `label == 1` is a real face), as established by the screen-replay bypass analysis of walkthrough 72. The value is defined exactly once, as `DEFAULT_MINIFASNET_LIVE_CLASS_INDEX` in `crates/inference-ort/src/pad.rs`; `soos-daemon`, `soos-enroll` and `soos-gui` construct the detector with `OrtPadDetector::new` and never pass an index (`new_with_class_index` / `with_live_class_index` are test-only, enforced by the repository invariant `test_no_pad_live_class_index_override_outside_tests`). The 2026-09-20 statement "Class 0 = Live, default 0" is obsolete, and the literal `2` that walkthrough 66 left in the daemon and the enrollment CLI was a security defect (GitHub #146: screen replays scored as live on the PAM path). An empirical re-measurement on real captures with the real model is tracked by PAD-06 (GitHub #172); any change of the index must go through this constant and a new ADR entry.
* **[2026-09-29] Multi-Frame PAD Consensus (GitHub #147):** The daemon never authorizes on a single capture. `Allow` requires `DEFAULT_PAD_CONSENSUS_REQUIRED = 3` consecutive distinct captures that are live at or above `pad_threshold` and match at or above `match_threshold`, inside a bounded window of `DEFAULT_PAD_CONSENSUS_WINDOW = 5` captures (`soos_policy::PadAggregator`, zero I/O). Any capture classified as a spoof (or with a non-finite liveness score) vetoes `Allow` for the entire request, and the veto cannot be reset within a request. The per-UID rate limiter records exactly one attempt per request; a rate-limit rejection at recording time downgrades `Allow` to `ProtocolError`/`RateLimited`.
* **[2026-09-29] Camera Preview Stream Exception (GitHub #143, CAM-01 / DMN-02):** `RequestKind::PreviewFrame` is the only channel through which camera frames may leave `soos-daemon`, exclusively towards the diagnostic GUI. The dispatcher serves it only after kernel `SO_PEERCRED` verification and: (a) the peer is root, or (b) `[preview] enabled = true` **and** the peer UID is listed in `[preview] allowed_uids` **and** `peer_uid == uid_hint` **and** the peer owns an active logind session. The section is absent/disabled by default (fail-closed), the allow-list is bounded to 64 UIDs, every preview request is rate limited per peer UID (default 40 per second, root included), refusals are standard `Response` messages (`ProtocolError`) with zero pixel bytes, and preview buffers are zeroized on drop. Frames never transit through the PAM module.
* **[2026-09-30] Single Camera Resolver & GUI Camera Ownership (GitHub #150, #152, CAM-02 / CAM-04):** `soos-daemon`, `soos-enroll` and `soos-gui` resolve the camera exclusively through `soos_camera_v4l::resolve_camera_device`: explicit path verbatim, otherwise the capture node matching `sensor_preference` (default `PreferIr`) through its `/dev/v4l/by-id/` alias, otherwise the `/dev/v4l/by-id/default-camera` sentinel. `""`, `auto` and `default` are sentinels everywhere. The daemon no longer silently replaces an explicit `camera_device` that is absent at startup (it was the only binary doing so). `soos-gui` opens `/dev/video*` directly only when the daemon is provably not running (socket `ENOENT`/`ECONNREFUSED` and `soos-daemon.service` inactive); in every other case it uses the daemon preview or shows a blocked notice, never a silent direct fallback.
