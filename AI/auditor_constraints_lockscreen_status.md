### Pre-existing violations found (not introduced by this change)
- P1 — `SessionValidator::any_session_matches` (crates/daemon/src/session.rs:101) does blocking `fs::read_dir` + per-file reads on a Tokio worker, with no cap on the number of directory entries; it also emits `warn!` per call when `/run/systemd/sessions` is missing. The new read path calls it (as the preview path already does); its cost is bounded here by constraint 12 (quota before the scan). Not blocking; candidate for a later `spawn_blocking`/entry cap.
- P2 — `RateLimiter` LRU eviction (crates/policy/src/rate_limit.rs:157-170) resets the history of an evicted UID; a quota bypass would require ≥ 64 distinct peer UIDs. Accepted existing design (R2), not blocking.
- No panic-path, `unsafe`, or stdout/stderr violation found in the production parts of crates/protocol/src/types.rs, crates/daemon/src/dispatcher.rs, crates/daemon/src/presence/worker.rs, crates/daemon/src/main.rs.
