### Missing tests for security properties (required additions)

These are new tests. The tester adds them as a Phase 2 addendum, or the developer adds them as new test functions. No existing assertion is changed. They must exist and pass before the candid review.

- **A-T1 (D-H, C14) — `Debug` redaction of every secret-bearing type.** No test pins it today. `test_rmc_client_hint_parsing` covers only `ClientHint`, and test 45 sees only what the exercised paths happen to log; a decimal byte array (`[12, 34, …]`) would pass its hex/base64 needles. Add `test_rmc_secret_types_debug_is_redacted` in `auth_store_tests.rs`. For each type listed in C14 that implements `Debug`, `format!("{:?}")` contains `<redacted>`. It contains none of these: the decimal list, hex or base64url of the token, credential id, public key, user handle, challenge, code or code hash. If a type has no `Debug`, an invariant test in `remote_passkey_contract.rs` instead asserts that the type's declaration has no `#[derive(…Debug…)]`.
- **A-T2 (C12c) — the lock file is never followed.** Test 29 creates `<path>.lock` as a regular file only. Add `test_rmc_credential_store_lock_file_is_never_followed` in `credentials_tests.rs`. It sets `<path>.lock` to a symlink to a file outside the directory. `update` returns `Err` (`Insecure` or `Io`), the symlink target's bytes and mode are unchanged, and the store file is not written.
- **A-T3 (C7b, spec §6 "a logged-in Funnel owner keeps ≥ 4 slots") — refused anonymous Funnel requests release their Funnel permit before lingering.** Test 54a checks only global permits for the tailnet, and test 55 does not keep the refused sockets open. Add `test_rmc_refused_anonymous_funnel_requests_never_hold_funnel_slots` in `auth_capacity_tests.rs`, built as follows. Hold `MAX_ANONYMOUS_FUNNEL_CONNECTIONS` anonymous requests with declared but unsent bodies on login/verify, or assets kept open. Then send 4 more anonymous Funnel requests that receive `503 busy`, and keep their sockets open (no clock advance). A session holder's `GET /api/status` over Funnel ⇒ `200` at once.
- **A-T4 (C8, C13) — production wiring and no blocking sleep on the runtime.** Add `test_rmc_s22_production_wiring_has_no_test_hooks` in `remote_passkey_contract.rs`, working on comment-stripped sources. `main.rs` calls `with_credentials_path(` and never `with_random(`, `with_file_owner_uid(` or `with_unix_clock(`. `server.rs` and `auth.rs` contain no `thread::sleep`.

### Recommended (not required)

- A server-level test showing that a tailnet `GET /api/status` completes while another process holds the store lock during a Funnel unlock persistence. This is the C8 behaviour proven end to end. With the paused clock it needs the store-lock wait to be an async sleep, which is exactly what C8 requires.
- `test_rmc_enroll_code_file_rules` has no future-dated case (the tester's deviation). End-to-end coverage in test 41 is accepted.

- Observation only, not a violation: `main.rs:119` logs `socket_path` at `info` (`/run/user/<uid>/soos-remote/remote.sock`). It was accepted by the 2026-10-05 ADR and must not be extended to the credential store path (C15).
